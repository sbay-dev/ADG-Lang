# بروتوكول إجماع تحكيم ADG-Lang

الإصدار: 1.0  
نطاق التطبيق: منصة `adg.sbay.sa` وحزم التحكيم العربية المرتبطة بها.

## 1. الغرض والحدود

يحدد هذا البروتوكول كيف تنتقل المهمة من التحكيم المستقل إلى نتيجة قابلة
للنشر مع حفظ الأدلة وحق الاعتراض. وهو مسار حوكمة برمجي قابل للتدقيق، وليس
اعتمادًا مؤسسيًا أو شهادة توافق مع معيار دولي بعينه. يستند تصميمه إلى مبادئ
المراجعة المستقلة، وفصل الأدوار، والإفصاح عن تعارض المصالح، وإمكان التتبع،
والتصعيد، والاستئناف.

قاعدة D1 هي مصدر حالة المهمة السلطوي. GitHub مرآة شفافة للأدلة المقبولة
والإيصالات، ولا يملك وحده ترقية حالة المهمة أو إلغاءها.

## 2. الأدوار والاستقلال

تتطلب كل نسخة مهمة أربعة حسابات مختلفة:

| الرمز | المسؤولية |
|---|---|
| A | تحكيم أول مستقل |
| B | تحكيم ثان مستقل لا يطلع على A قبل تثبيت مشاركته |
| J1 | مراجعة الاختلافات وإصدار القرار المقيد بالأدلة |
| J2 | تدقيق القرار والجذر والحزمة ثم الإجازة أو الرفض أو التنحي |

لا يجوز للحساب نفسه شغل أكثر من دور في نسخة المهمة أو عائلة العينة المحجوبة
ذاتها. يقر كل مشارك بالاستقلال وتعارض المصالح، وتبقى هويته الخاصة منفصلة عن
الدليل المنشور.

## 3. دورة الحالة

المسار العادي:

`draft → open → independent-review → discussion → final-review → approved → published`

مسار التصعيد:

`discussion/final-review/approved → escalated → reissued → independent-review`

وتوجد حالتا `revoked` و`failed` للإلغاء المعلل أو الفشل المقفل. كل انتقال
يكتب حدثًا دائمًا برقم نسخة متفائل؛ لا يسمح بطلب قديم أن يستبدل حالة أحدث.

## 4. الاتفاق المستقل

بعد قبول A وB تحسب المنصة:

- نسبة الاتفاق الخام؛
- معامل Cohen's kappa عندما يكون معرفًا؛
- عدد العناصر المتفقة والمختلفة والجذر المرتبط بكل مشاركة.

حدود العينة التجريبية هي اتفاق خام لا يقل عن `0.90` وkappa لا يقل عن
`0.80` عندما يكون معرفًا. عند تعذر تعريف kappa يستخدم الاتفاق الخام فقط.
هذه حدود تشغيلية للعينة وليست قاعدة عالمية لكل دراسة لغوية.

لا تعرض النتيجة السابقة للمحكّم إلا بعد تثبيت مشاركته المستقلة. بعدها يمكن
فتح نقاش مجهّل مرتبط بعنصر أو نتيجة أو حزمة محددة.

تبقى حزم A وB العامة في حالة `held` داخل المنصة حتى تثبيت المشاركتين معًا.
لا ترسل أي حزمة منفردة إلى Azure/GitHub، وإذا انتهت الجولة دون النصاب تلغى
الحزمة العامة المحتجزة مع بقاء سجلها الخاص للتدقيق.

## 5. القرار والإجازة

يقدم J1 قرارًا جديدًا لا ينسخ مشاركة A أو B، ويوثق سبب الترجيح لكل موضع
مختلف. يبني الخادم جذر القرار النهائي ولا يقبل إعلانًا نهائيًا غير مطابق
للمهمة والجولة النشطتين.

يفحص J2 الجذر والحزمة ودليل الاستقلال، ثم يختار:

- `ratify`: انتقال إلى `approved` وفتح نافذة الاستئناف؛
- `reject`: تصعيد وإعادة طرح تلقائية؛
- `recuse`: تصعيد وإعادة طرح تلقائية دون نسبة الخطأ إلى شخص.

لا توصف مشاركة سابقة بأنها خطأ شخصي قبل وجود نتيجة نهائية مجازة. بعد الإجازة
ترسل الإشعارات بصياغة علمية تشير إلى موضع الاختلاف والتعليق المرتبط.

## 6. الاستئناف والتصعيد

نافذة الاستئناف 14 يومًا من وقت الإجازة. يقبل الاستئناف من مشارك مرتبط
بالمهمة، ويجب أن يتضمن سببًا ومرجعًا قابلًا للمراجعة. الاستئناف المعلق يمنع
النشر.

يقبل المشرف الاستئناف أو يرفضه بمرجع قرار مسجل. القبول يسحب النتيجة النشطة،
يلغي إيصالها النهائي، ويحفظ الجولة السابقة بوصفها دليلًا تاريخيًا، ثم ينشئ
جولة جديدة. انخفاض الاتفاق، أو قرار J1 غير المطابق، أو رفض/تنحي J2 يؤدي
كذلك إلى إعادة طرح نسخة جديدة بدل تعديل الدليل السابق.

## 7. شرط النشر

`approved` نتيجة مؤقتة وليست منشورة. لا تتحول المهمة إلى `published` إلا
إذا تحققت جميع الشروط:

1. انتهاء نافذة الاستئناف؛
2. عدم وجود استئناف معلق؛
3. دمج سجل `adg-msa-task-state-v1` الموافق في المستودع؛
4. وصول إيصال HMAC صحيح يطابق المهمة والجولة والجذر والحدث؛
5. بقاء النتيجة النشطة دون سحب أو إعادة طرح.

ترد GitHub Actions إيصالات منفصلة لقبول الإرسالات والتعليقات. لا تعد حالة
`imported` أو `published` ناجحة قبل وصول إيصالها الصحيح إلى المنصة.

## 8. النقاش والمنشن والإشعارات

التعليقات مجهّلة في الواجهة العامة، وترتبط بمراجع محددة بدل نشر الهوية.
المنشن يقتصر على المشاركين المرتبطين بالمهمة، ويولد إشعارًا داخليًا وبريدًا
عند وجود موافقة اتصال. يستطيع المشرف إخفاء تعليق مع حفظ قرار الإشراف، ولا
يحذف سجل الدليل أو يعيد كتابة تاريخه.

## 9. التدقيق والخصوصية

تسجل الحالة والجولات والمقاييس والقرارات والاستئنافات والإيصالات في جداول
منفصلة. لا يرسل GitHub الاسم أو البريد أو الجوال أو حسابات التواصل. طلب محو
الهوية يحذف الارتباط الخاص وبيانات الدخول بعد إغلاق المهام وانقضاء مدة
الاحتفاظ، مع إبقاء الأدلة العلمية المجهّلة وسجل الإجماع.

أي تغيير في الحدود أو الأدوار أو مدة الاستئناف أو صيغة الإيصال يتطلب migration
ومراجعة اختبارات التكامل وتحديث هذا البروتوكول قبل النشر.
